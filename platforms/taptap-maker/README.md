# TapTap Maker

**Historical route:** browser creation chat and game preview.
**Public status:** operator procedure; unattended creation is not integrated.

## Connection and creation

Follow the [browser procedure](../shared/browser-workflow.md). Open
<https://maker.taptap.cn/> in the verified selected profile, create a fresh game,
record the visible mode label and leave defaults unchanged. The historical mode
label was not evidence of its underlying model or effort.

Enter the same prompt and click the actual send/play-shaped button. Verify the
message was accepted. Capture changing tool/progress messages before they
disappear. Keep monitoring within the agreed limit while a Stop/working state
remains, even if an intermediate build succeeded. Answer clarification using
the common policy; do not send repair prompts or purchase credits automatically.

## Game handoff

Identify the final preview and frame/crop; click inside it before keyboard tests.
Record browser zoom and frame size rather than assuming desktop coordinates
match another platform. Keep editor chat outside evaluator observations. Record
authentication requirements and freeze a permitted export only if available.

## Credits and historical identity

With permission, inspect the task's credit record and separately retain balance
delta and package price. Do not substitute a different day's cheaper run. The
owner-selected 09/20 example used 2,620 credits; it is **not** the 09/22 441-credit
sample in the older multi-platform reports. The displayed USD equivalent uses
a documented package price and exchange rate, not a new payment for that run.
Preserve conflicting readings and their sources rather than silently reconciling.
