# Local CLI creation reference

This is the procedure behind local creator samples, not an exact replay script
or a claim that a Harbor configuration has been validated in this public checkout.
Use a fresh isolated workspace and an explicitly approved account/model budget.

1. Record CLI version, requested model/effort, provider route, account-plan basis,
   allowed network/tools and the actual invocation. A successful `--version` is
   not proof that authentication or model access works. A live ping is a separately
   recorded model call, not free setup or part of the game creation timing.
2. Start a new conversation and empty game workspace. No resume, previous game,
   repository instructions, private skills or prior scores. Record any scaffold
   that must exist. Keep the approved prompt bytes unchanged; the historical
   Tetris prompt was `一个经典俄罗斯方块`.
3. Capture native CLI events and timestamps privately. Confirm prompt acceptance,
   answer clarification under the comparison's common policy, and retain every
   added instruction. No silent repair/regeneration or extra attempts.
4. Retain final response, exit status and generated files. An exit code or the
   agent saying "done" does not establish a playable game. Record the build/start
   recipe without changing the submitted game. Freeze the runnable bundle with
   hashes and preserve the original separately from any later fix.
5. Serve only the reviewed game directory on loopback, not the repo, home or raw
   job directory. Give an independent evaluator the task and game surface, never
   creator dialogue, source, provider labels or cost records.

For supported Harbor tasks, prefer its installed agent implementation and native
job/trajectory/artifact collection. Do not fabricate native Harbor results for
historical operator-run CLI sessions. Model network access and credential delivery
need a reviewed creator configuration; the verifier must retain its own isolation.

## Record and compare

Use [record.example.json](record.example.json) as an optional private worksheet;
it is not a replacement for Harbor JSON and is not consumed by the counter verifier.
Retain requested **and observed** model/effort, CLI/provider identity, native usage
semantics, and source of each measurement. Cached input may already be included
in total input. Do not sum overlapping token categories.

A CLI cost number, an API-equivalent token estimate and an allocated subscription
charge are different things. Preserve the native cost and its pricing confidence;
do not call it an actual bill. Subscription usage with unknown allocation is
unknown, not zero. Keep setup, creator, evaluator and operator durations separate.
